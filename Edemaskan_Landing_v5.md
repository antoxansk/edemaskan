# ЧАСТЬ 4. FEATURE_SPEC #2 — Live-уведомления (social proof toasts)

> **Проект:** Edemaskan landing
> **Приоритет:** High
> **Оценка:** 3–4 часа

## 1. User Story

**Как** посетитель лендинга,
**я хочу** видеть, что прямо сейчас другие люди проходят сканирование,
**чтобы** ощутить, что сервис активен и популярен, и снизить барьер к собственному клику.

### Сценарий

1. Пользователь открывает страницу `/morning-face` или `/scan`
2. Через **первые 15 секунд** после загрузки появляется первое уведомление в левом нижнем углу: «**Ольга из Новосибирска** только что прошла сканирование · 2 минуты назад»
3. Уведомление держится 5 секунд, плавно исчезает
4. Через **рандомный интервал 20–60 секунд** появляется следующее уведомление с другим именем/городом/временем
5. И так далее, пока пользователь на странице

### Критерии приёмки

- [ ] Уведомления появляются на двух страницах: `/morning-face` и `/scan` (шаг фотографирования)
- [ ] Первое уведомление — через 15с после загрузки страницы (не сразу, чтобы не пугать)
- [ ] Интервалы между показами **рандомные**: от 20 до 60 секунд (не фиксированные 40с)
- [ ] Длительность показа одного уведомления: 5 секунд
- [ ] Имена — русские + СНГ женские, города — российские (включая маленькие)
- [ ] Имя и город при каждом показе разные (не повторять одно за другим)
- [ ] Текст действия — одна из 3 формулировок (см. ниже)
- [ ] Время в уведомлении — одна из формулировок «несколько секунд / N минут назад» (рандом 1–7 минут)
- [ ] Анимация появления: slide-in слева снизу + fade-in (300ms)
- [ ] Анимация исчезновения: fade-out + slide-out (300ms)
- [ ] При hover на уведомление (десктоп) — пауза таймера, чтобы можно было дочитать
- [ ] На мобиле уведомления не перекрывают CTA-кнопку и Sticky Bottom CTA
- [ ] Уведомления **прекращаются**, когда пользователь скроллит до футера (зачем мешать, если он уже всё прочитал)

## 4. Логика появления

```typescript
// Псевдокод
function startNotifications() {
  // Первый показ через 15 секунд
  setTimeout(showNotification, 15000);
}

function showNotification() {
  const notification = generateRandom();
  // notification = {
  //   name: random(FEMALE_NAMES),
  //   city: random(RUSSIAN_CITIES),
  //   action: random(ACTIONS),
  //   time: random(TIMES)
  // }
  
  // Не повторять то же имя и город что было в предыдущем
  if (notification.name === lastShown.name) return showNotification();
  if (notification.city === lastShown.city) return showNotification();
  
  renderToast(notification);
  
  // Скрыть через 5 секунд
  setTimeout(hideToast, 5000);
  
  // Запланировать следующее через рандомный интервал 20-60 секунд
  const nextDelay = randomBetween(20000, 60000);
  setTimeout(showNotification, nextDelay);
  
  lastShown = notification;
}

function randomBetween(min, max) {
  return Math.floor(Math.random() * (max - min + 1)) + min;
}
```

## 5. Edge Cases

| # | Ситуация | Поведение |
|---|----------|-----------|
| 1 | Пользователь скроллит к футеру | Уведомления прекращаются (вызвать `clearAllTimers()`) |
| 2 | Пользователь свернул вкладку (`document.hidden = true`) | Таймеры на паузе, при возврате — продолжить с того же места |
| 3 | На мобиле уведомление закрывает Sticky Bottom CTA | Уведомление позиционируется выше CTA (`bottom: 80px`), не перекрывает |
| 4 | Пользователь закрыл крестиком | Текущее скрывается мгновенно, следующее всё равно появится через 20–60с |
| 5 | prefers-reduced-motion | Анимации появления/исчезновения отключены, уведомление просто появляется и исчезает |
| 6 | Два уведомления хотят появиться одновременно | Только одно в каждый момент времени — следующий setTimeout стартует только после скрытия текущего |
| 7 | Пользователь на странице больше часа | Никаких лимитов, продолжаются. Если выглядит спамом — добавить лимит 30 уведомлений за сессию |

# ЧАСТЬ 5. FEATURE_SPEC #3 — Count-up анимация цифр

> **Приоритет:** Medium
> **Оценка:** 1 час

## 1. User Story

**Как** посетитель лендинга,
**я хочу** видеть, как цифры на полосе достижений (327+, 3 000+, 30 000+) «отсчитываются» с 0 до своих значений при появлении на экране,
**чтобы** обратить на них внимание и почувствовать масштаб.

### Сценарий

1. Пользователь скроллит со страницы 1 на страницу 2
2. Полоса цифр входит в viewport
3. Все 4 ячейки одновременно начинают анимацию count-up:
   - 0 → 327 за 1.5 секунды
   - 0 → 3 000 за 1.5 секунды
   - 0 → 30 000 за 1.5 секунды
   - «Сеченова» — без анимации (это не число), но появляется с fade-in
4. После окончания анимации цифры остаются на финальных значениях
5. Если пользователь скроллит вверх и обратно — анимация **не повторяется** (только один раз за сессию)

### Критерии приёмки

- [ ] Анимация запускается, когда полоса цифр на 50% видима в viewport (`IntersectionObserver`)
- [ ] Длительность count-up: 1500ms
- [ ] Easing: `easeOutCubic` (быстрый старт, медленное завершение — выглядит «солиднее»)
- [ ] Цифры с разделителями тысяч: «3 000» а не «3000»
- [ ] Знак «+» появляется в самом конце (после достижения финального числа), не в процессе
- [ ] При `prefers-reduced-motion: reduce` — анимация отключена, числа показываются сразу
- [ ] Срабатывает один раз за сессию (флаг в state или sessionStorage)

---

## 2. Реализация

### Вариант A — библиотека (быстро)

```tsx

import { useInView } from 'react-intersection-observer';

function StatCell({ value, label, suffix = '+' }) {
  const { ref, inView } = useInView({ triggerOnce: true, threshold: 0.5 });
```

# ЧАСТЬ 6. FEATURE_SPEC #4 — Sticky Bottom CTA (мобайл)

> **Приоритет:** High
> **Оценка:** 1–2 часа

## 1. User Story

**Как** мобильный пользователь,
**я хочу** всегда видеть основную CTA-кнопку под пальцем при скролле,
**чтобы** в любой момент чтения мог быстро перейти к сканированию без необходимости скроллить наверх.

### Сценарий

1. Пользователь открывает `/morning-face` на телефоне
2. На первом экране Sticky CTA **не виден** (основная большая CTA и так на экране)
3. Когда пользователь скроллит вниз и основная CTA уходит за пределы viewport — снизу плавно выезжает компактная Sticky CTA
4. Sticky CTA остаётся видимой всё время скролла
5. Когда пользователь доскроллил до футера — Sticky CTA исчезает (всё, прочитано)

### Критерии приёмки

- [ ] Показывается только на мобиле и планшетах (`<lg`, то есть ширина < 1024px)
- [ ] На десктопе — скрыта (`hidden lg:hidden`)
- [ ] Не показывается, пока пользователь видит основную CTA первого экрана
- [ ] Появляется, когда основная CTA уходит за пределы viewport
- [ ] Исчезает, когда пользователь доскроллил до футера (или до последней CTA Экрана 4 — чтобы не дублировать)
- [ ] Анимация появления: slide-up + fade-in, 250ms
- [ ] Высота: 64px, не больше — не должна закрывать половину контента
- [ ] При клике — тот же редирект, что и у основной CTA (`/scan?from=morning-face`)
- [ ] При клике — счётчик инкрементируется (после успешного сканирования, как обычно)
- [ ] Не перекрывает Live-уведомления (они позиционируются выше: `bottom: 80px`)

## 2. Дизайн

```
┌─────────────────────────────────────────┐
│                                         │
│         Основной контент                │
│                                         │
├─────────────────────────────────────────┤
│  [ → Узнать причину своего отёка ]     │  ← Sticky CTA (64px)
└─────────────────────────────────────────┘
```

### Визуал

- **Контейнер:** `position: fixed`, `bottom: 0`, `left: 0`, `right: 0`, `z-index: 40`
- **Фон контейнера:** белый с легчайшим backdrop-blur, top-border 1px solid `--color-border`
- **Высота:** 64px, padding 12px по бокам
- **CTA-кнопка внутри:** та же зелёная переливающаяся, но компактная — `py-3 px-6`, `text-base font-bold`, ширина 100% от контейнера
- **Иконка:** стрелка → справа
- **Safe-area:** обязательно `padding-bottom: env(safe-area-inset-bottom)` для iPhone с «домашней линией»

### CSS

```css
.sticky-cta {
  position: fixed;
  bottom: 0;
  left: 0;
  right: 0;
  z-index: 40;
  padding: 12px 16px calc(12px + env(safe-area-inset-bottom));
  background: rgba(255, 255, 255, 0.95);
  backdrop-filter: blur(8px);
  border-top: 1px solid var(--color-border);
  transform: translateY(100%);
  transition: transform 250ms ease-out;
}

.sticky-cta.visible {
  transform: translateY(0);
}

@media (min-width: 1024px) {
  .sticky-cta { display: none; }
}
```

## 3. Логика появления

```typescript
// Псевдокод
const heroCtaRef = useRef(null);
const footerRef = useRef(null);
const [isVisible, setIsVisible] = useState(false);

useEffect(() => {
  const heroObserver = new IntersectionObserver(
    ([entry]) => {
      // Появляется, когда основная CTA УШЛА из viewport
      if (!entry.isIntersecting) setIsVisible(true);
      else setIsVisible(false);
    },
    { threshold: 0 }
  );
  heroObserver.observe(heroCtaRef.current);

  const footerObserver = new IntersectionObserver(
    ([entry]) => {
      // Скрывается, когда виден футер
      if (entry.isIntersecting) setIsVisible(false);
    },
    { threshold: 0.1 }
  );
  footerObserver.observe(footerRef.current);

  return () => {
    heroObserver.disconnect();
    footerObserver.disconnect();
  };
}, []);
```

## 4. Edge Cases

| # | Ситуация | Поведение |
|---|----------|-----------|
| 1 | Десктоп (≥1024px) | Не показывается вообще |
| 2 | Пользователь видит основную CTA первого экрана | Sticky скрыт |
| 3 | Пользователь видит футер | Sticky скрыт |
| 4 | iPhone с «домашней линией» (X и новее) | `env(safe-area-inset-bottom)` обеспечивает отступ снизу |
| 5 | Открыта мобильная клавиатура | Sticky не должна перекрывать инпут — но на этом лендинге инпутов нет, кейс не критичен |
| 6 | Уведомление Social Proof появилось одновременно | Уведомление позиционируется выше Sticky (`bottom: 80px`), не конфликтуют |
| 7 | prefers-reduced-motion | Sticky появляется/исчезает без анимации (просто display: block/none) |
