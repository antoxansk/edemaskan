# FEATURE_SPEC — AI Face Zone Detection & Overlay

> **Проект:** Edemaskan / УПДН AI-сканирование
> **Страница:** результат сканирования (`/scan/result` или аналог)
> **Приоритет:** High
> **Оценка:** 12–16 часов (1.5–2 рабочих дня)
> **Дата:** 2026-05-18

---

## 1. Контекст и проблема

### Текущая реализация (что не так)

На странице результата сканирования над фото лица пользователя накладываются цветные овалы, обозначающие проблемные зоны (отёчность по зонам). **Сейчас овалы статичны и не привязаны к анатомии лица:**

- Овалы случайного размера, часто крупнее самой зоны
- Выходят за контуры лица (виден овал на фоне)
- Не учитывают поворот головы, наклон, расстояние до камеры
- Не учитывают индивидуальную геометрию лица (узкое/широкое, высокий/низкий лоб и т.д.)

**Результат:** разметка выглядит непрофессионально и подрывает доверие к AI-анализу. Пользователь видит «нарисованные кружки», а не точную диагностику.

### Эталонный пример (`revitonica.ru` — Image 2)

- Контуры зон точно следуют анатомии конкретного лица
- Зоны разноцветные, не перекрываются грубо
- Под фото — кликабельные теги зон («Овал лица», «Область лба», «Брови и межбровка», «Периорбитальная зона», «Носогубная зона», «Губы и кисетки», «Подбородочная зона», «Шея»)
- При клике на тег — соответствующая зона на фото подсвечивается + появляется текстовое описание зоны
- Зоны видны только при выборе — не все одновременно (так чище визуально)

### Цель фичи

Заменить статичные overlay'и на **AI-определяемые контуры зон**, привязанные к 468 ключевым точкам лица (face landmarks). Каждая зона рисуется по своей группе точек, что даёт точное прилегание независимо от ракурса и геометрии лица.

## 2. User Story

**Как** пользователь, прошедший сканирование,
**я хочу** видеть на своём фото точную разметку зон лица — там, где они действительно находятся,
**чтобы** доверять результату AI-анализа и понимать, какая зона за что отвечает.

### Сценарий использования

1. Пользователь загрузил 4 фото лица и ответил на 5 вопросов на `/scan`
2. Откравается страница результата `/scan/result`
3. На фронтальном фото лица **AI-модель определяет 468 face landmarks** (точек) за 200–500мс
4. На основе landmarks отрисовываются контуры **8 зон лица** (см. список в §4)
5. По умолчанию показано фото без контуров + теги зон под фото (как в эталоне)
6. Пользователь кликает на тег зоны → соответствующий контур подсвечивается на фото, появляется текст разбора этой зоны
7. Пользователь может переключаться между зонами

### Критерии приёмки

- [ ] Контуры зон рисуются на основе **реальных landmarks конкретного фото**, а не статичных координат
- [ ] Контуры точно прилегают к границам зоны (не вылезают за пределы лица)
- [ ] Поддерживается **8 зон**: овал лица, область лба, брови и межбровка, периорбитальная зона, носогубная зона, губы и кисетки, подбородочная зона, шея
- [ ] Поведение клика на тег зоны: показ только этого контура + текст разбора
- [ ] Время отрисовки контуров после загрузки страницы — **не более 1 секунды**
- [ ] Корректная работа при углах поворота головы до ±15°
- [ ] Fallback: если landmarks не определились — показать честное сообщение, а не «кривые овалы»

## 3. Технологический стек

### Основное решение — MediaPipe Face Mesh (Google)

Используем **MediaPipe Face Mesh** через `@mediapipe/face_mesh` или `@tensorflow-models/face-landmarks-detection`.

**Почему именно она:**
- 468 точек на лице (этого с запасом хватает на все 8 зон)
- Работает прямо в браузере (WebAssembly), не требует сервера для inference
- Бесплатно, лицензия Apache 2.0
- Поддерживает поворот головы до ~45° и разные ракурсы
- Inference 100–300мс на современном смартфоне
- Документация и готовые примеры от Google

### Альтернатива (если MediaPipe не зайдёт)

`face-api.js` — 68 точек (меньше детализации, но проще в интеграции). Подойдёт, если нужна совсем лёгкая реализация без контуров со многими точками.

**Рекомендую начать с MediaPipe** — она даёт визуально лучший результат.

### Где запускается inference

**Вариант A — клиентский (рекомендуется):** WebAssembly в браузере. Минусы — первая загрузка модели ~5–10MB. Плюсы — фото не уходит с устройства, GDPR/152-ФЗ соблюдены без хлопот.

**Вариант B — серверный:** Python + MediaPipe на backend. Минусы — нужно слать фото на сервер, обрабатывать, возвращать landmarks. Плюсы — модель кэшируется один раз. Имеет смысл, если у проекта уже есть backend для других AI-задач.

Поскольку в УПДН уже декларируется «мы не сохраняем фотографии» — **клиентский вариант предпочтительнее**, он этой обещанию соответствует автоматически.

Носогубные складки — от крыла носа к уголку рта, с обеих сторон.

### 4.7 Подбородочная зона

Нижняя часть лица — от уголков рта до контура челюсти, включая подбородок.

```javascript
const CHIN = [
```

**Стиль:** замкнутый многоугольник

### 4.8 Шея

Зона ниже подбородка. **Внимание:** MediaPipe Face Mesh **не включает точки шеи** напрямую. Решение — вычислить зону шеи геометрически: от точек нижней челюсти (172, 152, 397) опустить вертикально на 30% высоты лица.

```javascript
// Псевдокод
function getNeckRegion(landmarks, faceHeight) {
  const jawCenter = landmarks[152];
  const neckTop = { x: jawCenter.x, y: jawCenter.y };
  const neckBottom = { x: jawCenter.x, y: jawCenter.y + faceHeight * 0.3 };
  // Ширина шеи ≈ 60% ширины нижней челюсти
  return computeOval(neckTop, neckBottom, jawWidth * 0.6);
}
```

**Цвет:** голубой `#0EA5E9`
**Стиль:** вытянутый овал

### 5.3 Поведение зон на фото

- **По умолчанию (initial state):** ни одна зона не выбрана, на фото нет overlay. Это даёт чистый «портрет», а пользователь сам решает, что смотреть.
- **При клике на тег зоны:** на фото плавно (300ms fade-in) появляется только эта зона. Предыдущая, если была, плавно исчезает.
- **При повторном клике на ту же зону:** overlay скрывается (toggle), возвращается чистое фото.
- **Описание зоны:** появляется блок снизу с заголовком и AI-текстом разбора этой зоны.

### 5.4 Подсветка зоны на фото

- Контур зоны: 2.5px solid цвет зоны
- Заполнение: цвет зоны с opacity 0.2
- Glow-эффект вокруг контура: `box-shadow: 0 0 12px rgba({color}, 0.5)` или SVG filter `feGaussianBlur`
- Плавная пульсация контура (опционально): opacity 0.7 → 1.0 → 0.7, длительность 2с, infinite

## 6. Реализация — пошагово

### Шаг 1. Подключение MediaPipe

```bash
npm install @mediapipe/face_mesh @mediapipe/camera_utils @mediapipe/drawing_utils
# или через TFJS:
npm install @tensorflow-models/face-landmarks-detection @tensorflow/tfjs-backend-webgl
```

### Шаг 2. Inference на загруженном фото

```typescript
// src/lib/face-detection/detect.ts
import * as faceLandmarksDetection from '@tensorflow-models/face-landmarks-detection';

let detectorPromise: Promise<faceLandmarksDetection.FaceLandmarksDetector> | null = null;

async function getDetector() {
  if (!detectorPromise) {
    detectorPromise = faceLandmarksDetection.createDetector(
      faceLandmarksDetection.SupportedModels.MediaPipeFaceMesh,
      { runtime: 'tfjs', refineLandmarks: true, maxFaces: 1 }
    );
  }
  return detectorPromise;
}

export async function detectFaceLandmarks(imageElement: HTMLImageElement) {
  const detector = await getDetector();
  const faces = await detector.estimateFaces(imageElement);
  if (faces.length === 0) return null;
  return faces[0].keypoints; // массив 468 точек {x, y, z}
}
```

### Шаг 3. Отрисовка зоны через SVG

```typescript
// src/components/FaceZoneOverlay.tsx
import { FACE_ZONES } from '@/lib/face-detection/zones';

function FaceZoneOverlay({ landmarks, activeZone, imageWidth, imageHeight }) {
  if (!activeZone || !landmarks) return null;
  
  const zoneIndices = FACE_ZONES[activeZone].indices;
  const points = zoneIndices
    .map(i => `${landmarks[i].x},${landmarks[i].y}`)
    .join(' ');

  return (
    <svg
      viewBox={`0 0 ${imageWidth} ${imageHeight}`}
      className="absolute inset-0 w-full h-full pointer-events-none"
    >
      <polygon
        points={points}
        fill={FACE_ZONES[activeZone].color}
        fillOpacity="0.2"
        stroke={FACE_ZONES[activeZone].color}
        strokeWidth="2.5"
        className="zone-pulse"
      />
    </svg>
  );
}
```

### Шаг 4. AI-разбор зоны (текст)

Когда зона активна, под фото показывается текст. Текст можно генерить двумя способами:

**Вариант A — заранее на этапе сканирования.** При обработке фото backend (или сам клиент) формирует JSON с описаниями всех 8 зон через LLM (Claude/GPT-4 Vision). При клике на тег — берём готовый текст.

**Вариант B — on-demand при клике.** Дольше, дороже, но позволяет диалоговый формат («Расскажи подробнее»).

Рекомендую **вариант A** — быстрее, дешевле, проще.

## 7. Edge Cases

| # | Ситуация | Поведение |
|---|----------|-----------|
| 1 | Лицо не определилось (плохое освещение, очки, маска) | Не показываем overlay, выводим сообщение: «Не удалось точно определить контуры лица. Попробуйте загрузить фото при дневном свете, без очков и аксессуаров.» + кнопка «Загрузить другое фото» |
| 2 | На фото несколько лиц | Используем самое крупное (центральное), остальные игнорируем (`maxFaces: 1` в конфиге) |
| 3 | Сильный наклон головы (>30°) | Landmarks всё равно определятся, но качество ниже. Если confidence модели <0.7 — показать предупреждение «Фото повёрнуто, разметка может быть неточной» |
| 4 | Очень маленькое лицо в кадре (<20% высоты) | Сообщение: «Подойдите ближе к камере и сделайте фото заново» |
| 5 | Лицо в профиль | MediaPipe требует фронтальный ракурс. Для профиля — fallback на статичную разметку или сообщение «Загрузите фронтальное фото» |
| 6 | Inference занимает >3 секунд (старое устройство) | Loading state со spinner'ом и сообщением «AI анализирует ваше фото...» |
| 7 | Модель не загрузилась (нет интернета или CDN недоступен) | Retry 3 раза с экспонентой, потом fallback на статичные овалы (как сейчас) с пометкой «Точная разметка временно недоступна» |
| 8 | Браузер не поддерживает WebGL | TFJS автоматически переключается на CPU backend — медленнее, но работает. Если совсем не поддерживается — fallback на серверный inference |
| 9 | Пользователь сразу переключает зоны (быстрые клики) | Debounce 100мс на переключение, чтобы анимации не накладывались |
| 10 | Фото в EXIF повёрнуто (iPhone иногда так делает) | Перед inference читаем EXIF orientation и поворачиваем canvas |

## 8. Performance

### Целевые метрики

- **Загрузка модели:** первая загрузка 5–10MB, кэшируется браузером. После первого визита — 0мс
- **Inference на одном фото:** 100–500мс на смартфоне 2022+ года, до 1.5с на старых устройствах
- **Отрисовка SVG-контура:** <16мс (60fps)
- **Переключение между зонами:** 300мс fade-in/fade-out

### Оптимизации

- Lazy-load модели — грузим только когда пользователь дошёл до страницы результата, а не на лендинге
- Web Worker для inference, чтобы не блокировать UI (опционально)
- Уменьшение разрешения фото до 640px перед inference (точности хватает, скорость x3)
- Кэширование landmarks в `sessionStorage` — если пользователь обновит страницу, не пересчитываем

## 10. Acceptance Demo

Перед сдачей фичи технарь демонстрирует на 5 разных лицах:

1. **Классический фронтальный портрет, нейтральное освещение** — все 8 зон рисуются точно
2. **Лицо с лёгким наклоном (~10°)** — зоны корректно следуют наклону
3. **Худое лицо** — контуры узкие, не вылезают на фон
4. **Полное лицо** — контуры широкие, охватывают всю зону
5. **Сложный кейс — пользователь в очках** — fallback-сообщение либо корректная работа с учётом очков

Каждый кейс проверяется на **iOS Safari, Android Chrome, Desktop Chrome, Desktop Safari**.
